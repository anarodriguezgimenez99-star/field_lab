# FIELD LAB UX model

FIELD LAB is organized around one loop:

`COLLECT → LAB → LEARN`

- **Collect** is where references, images, URLs, notes, ideas and resources land. Classification is optional at capture time; source, project, tool and tags are metadata and filters.
- **Lab** is where the user tests a real idea. An Experiment contains setup, input references, multiple Experiment Runs, observations, comparison and a conclusion.
- **Learn** is where reusable knowledge lives. Learnings, Recipes and Prompt Blocks share one surface; Prompt Deck is a contextual action (`Build Prompt`), not a destination.

## Context, not navigation

Projects and Tools remain first-class domain models, but they are context selectors and metadata. Flows remain advanced knowledge. MCP, Activity and agent permissions live under Settings → AI Connections. Agent proposals appear as AI Suggestions inside Learn and never create experiments automatically.

## Provenance

Saving an Experiment conclusion as a Learning stores the source Experiment and Best Run IDs in the Learning metadata, while preserving project and tool relationships. This keeps the answer to “where did this Learning come from?” available without making provenance a separate destination.

## Platform shape

- macOS: a narrow sidebar with Collect, Lab, Learn and Settings; Lab opens by default.
- iPhone: three tabs only—Collect, Lab and Learn—with Settings in the toolbar.
- Search is contextual in the toolbar and spans Collect, Experiments and Learn.
